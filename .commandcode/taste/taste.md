# Taste

- Prefers plain-language, high-level feature overviews and direct tool recommendations before technical specs and long decision lists. Confidence: 0.7
- Wants a concise recap of the feature/scope confirmed with him before the agent digs into code or starts implementing (explicit go-ahead gate before investigation). Confidence: 0.6
- Strongly dislikes placeholder/no-op UI controls and false or unearned claims; wants toggles and UI to be backed by real, working behavior ("it should have actual haptics", "made actual"). Confidence: 0.8
- Pragmatic about placeholders only when the underlying capability genuinely does not exist yet (e.g. export deferred until the emotion pipeline exists), and wants such gaps stated honestly rather than faked. Confidence: 0.7
- Wants privacy/feature-sensitive access to be user-controlled, with permissions the user can explicitly grant or revoke. Confidence: 0.7
